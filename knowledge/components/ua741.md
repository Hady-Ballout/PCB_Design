# Op amp (uA741)

The classic 8-pin DIP single op amp. Use this instead of the generic
[opamp.md](opamp.md) kind when you specifically want the uA741's physical
DIP-8 pinout to carry through to the schematic and footprint (`Package_DIP:
DIP-8_W7.62mm`) — for example when following a datasheet or tutorial that
gives pin numbers.

## Pin contract

`nodes` must list exactly 8 net names, in this order — this is `fixedPins`,
so it is also the physical DIP-8 pin order (pins 1–8), unlike the generic
`opamp` kind:

| # | Pin | Role |
|---|-----|------|
| 1 | `OFS1` | Offset null. Leave `NC_<REF>_1` unless doing an offset-trim circuit with a trim pot to `V-`. |
| 2 | `IN-` | Inverting input. Almost always part of a feedback network. |
| 3 | `IN+` | Non-inverting input. Must connect to something — see Wiring rules. |
| 4 | `V-` | Negative supply, or ground for a single-supply design. |
| 5 | `OFS2` | Offset null. Leave `NC_<REF>_5` alongside `OFS1` unless trimming. |
| 6 | `OUT` | Output. |
| 7 | `V+` | Positive supply. |
| 8 | `NC` | No internal connection. Leave `NC_<REF>_8`. |

Ground is `"0"`. For a pin you deliberately leave unconnected use
`"NC_<REF>_<pinNumber>"`.

## Value

Free-form part number, e.g. `"uA741"`, `"LM741"`. It is documentation only —
the SPICE export always uses the fixed `UA741` subcircuit regardless of the
string here.

## Wiring rules

Same electrical rules as [opamp.md](opamp.md), mapped onto the DIP-8 pin
order:

- **Both inputs must connect to something other than the chip itself.**
  `opamp_input_floating` checks `ua741` using pins 3 (`IN+`) and 2 (`IN-`) —
  same rule as the generic op amp, just at different node-array indices. Tie
  `IN+` to a reference and loop `IN-` into a feedback network (even a direct
  wire to `OUT` for a buffer).
- **`OFS1`/`OFS2`/`NC` normally ride `NC_<REF>_<pinNumber>` nets.** Only wire
  them up if you are building an offset-null trim circuit; leaving them
  unconnected is the correct default, not an omission.
- **Supply pins need real power**, and for single-supply designs tie `V-` to
  `"0"` — same headroom caveat as the generic op amp: the output cannot swing
  below `V-`.
- With two or more analog ICs (a second uA741, a 555, etc.) sharing a supply
  and no decoupling capacitor anywhere from the supply rail to ground, expect
  a `missing_supply_decoupling` warning — add a 100 nF cap across `V+`/`V-`
  (or `V+`/ground) near the chip.

## Worked example

Unity-gain follower on a 9 V single supply:

```json
{ "ref": "XU1", "kind": "ua741", "value": "uA741",
  "nodes": ["NC_XU1_1", "VOUT", "VIN", "0", "NC_XU1_5", "VOUT", "VCC", "NC_XU1_8"] }
```

Pin 2 (`IN-`) and pin 6 (`OUT`) share the `VOUT` net — that feedback loop
makes it a buffer and satisfies `opamp_input_floating` for the inverting
input. Pin 3 (`IN+`) is `VIN`, which needs its own connection elsewhere in the
circuit (a source or bias divider) to avoid `opamp_input_floating` on the
non-inverting side too.

## Gotchas

- **The input order is reversed from the generic `opamp` kind's array
  position.** `opamp` lists `[IN+, IN-, ...]` at indices 0/1; `ua741` lists
  `[OFS1, IN-, IN+, ...]`, so `IN-` is index 1 and `IN+` is index 2. Copying a
  node array between the two kinds without checking the table above silently
  swaps the inputs.
- Eight nodes are required even though five are almost always `NC_*` —
  `fixed_pin_node_count` flags a short array, but nothing catches nodes
  listed in the wrong physical slot.
- The SPICE behaviour is the fixed `UA741` subcircuit regardless of the
  `value` string; do not read simulation results as validating a different
  real part.
